= OpenBangla Keyboard — Bangla Keyboard for Linux | IBus & Fcitx5

image:https://img.shields.io/badge/platform-Linux-333333?logo=linux&logoColor=white[Linux] image:https://img.shields.io/badge/input%20method-IBus%20%7C%20Fcitx5-0F6CBD[Input methods] image:https://img.shields.io/badge/build-CMake-064F8C?logo=cmake&logoColor=white[CMake] image:https://img.shields.io/badge/UI-Qt5-41CD52?logo=qt&logoColor=white[Qt5] image:https://img.shields.io/badge/C%2B%2B%20%7C%20Rust-00599C?logo=rust&logoColor=white[C++ and Rust]

OpenBangla Keyboard is an open-source, Unicode-compliant **Bangla (Bengali) keyboard and input method for Linux**. It provides phonetic and fixed keyboard layouts, typing automation, dictionary support and autocorrection.

This project provides a Linux-focused distribution of OpenBangla Keyboard with prebuilt releases, bundled runtime libraries, and a user-local installation workflow for conventional Linux desktops and immutable or image-based Linux systems.

== What OpenBangla Keyboard provides

* **Prebuilt Linux releases** for x86_64 and ARM64.
* **Automatic backend selection:** KDE Plasma uses Fcitx5; other desktop environments use IBus.
* **User-local installation** under `~/.local` without a system-wide package install.
* **Source builds** remain available through `tools/build.sh`.
* **Isolated source builds** using Toolbx, Distrobox, Podman, or Docker.
* **Bundled Qt5 and required runtime libraries** for the user-local installation.
* **Automatic IBus component registration** for user-local installations.
* **User-local uninstaller** with optional cache removal.

== Bangla keyboard and input-method features

The OpenBangla Keyboard codebase is built for Bangla typing on Linux and includes:

* Phonetic Bangla typing, including Avro-style phonetic input.
* Fixed Bangla keyboard layouts.
* Unicode-compliant Bengali text input.
* Typing automation for fixed layouts.
* Dictionary-based suggestions and autocorrection.
* A Qt-based configuration interface.
* Linux desktop integration through IBus or Fcitx5.

== Installation

=== Prebuilt installation

Normal users do not need a compiler, CMake, Rust, Qt development packages, or a build container. The installer downloads the matching prebuilt Linux release for the current architecture and desktop environment, verifies its checksum, and installs it for the current user.

Supported architectures:

* x86_64
* ARM64 (aarch64)

KDE Plasma automatically uses Fcitx5. Other desktop environments automatically use IBus.

Install:

[source,bash]
----
git clone https://github.com/hasanmuammar/OpenBangla-Keyboard.git
cd OpenBangla-Keyboard
bash tools/install.sh
----

To install a specific release:

[source,bash]
----
bash tools/install.sh --version 3.0.0
----

=== Build from source

For development, local compilation, or release packaging, use the separate source-build script:

[source,bash]
----
bash tools/build.sh
----

The source build can use Toolbx, Distrobox, Podman, or Docker to keep build dependencies out of the host system. Release packages are produced for both x86_64 and ARM64 by GitHub Actions.

[source,bash]
----
bash tools/build.sh --backend ibus --package
bash tools/build.sh --backend fcitx --package
----

== Uninstallation

Remove the current-user prebuilt installation:

[source,bash]
----
bash tools/uninstall.sh
----

To remove the build and staging cache as well:

[source,bash]
----
bash tools/uninstall.sh --purge-cache
----

== Manual Linux build

The CMake project supports one input-method backend per build.

=== IBus

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=ON \
  -DENABLE_FCITX=OFF

cmake --build build --parallel 2
cmake --install build
----

=== Fcitx5

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=OFF \
  -DENABLE_FCITX=ON

cmake --build build --parallel 2
cmake --install build
----

The build requires Qt5, CMake, Ninja, a C/C++ compiler, Rust/Cargo, zstd development files, and the development files for the selected input-method backend.

== Development

The project is developed on the `develop` branch.

For normal use, `tools/install.sh` downloads a prebuilt release. For source development and local compilation, use `tools/build.sh`.

[source,bash]
----
git pull --recurse-submodules
bash tools/build.sh
----

For a clean automated rebuild:

[source,bash]
----
rm -rf "$XDG_CACHE_HOME/openbangla-keyboard/build"
----

If `XDG_CACHE_HOME` is not set:

[source,bash]
----
rm -rf "$HOME/.cache/openbangla-keyboard/build"
----

Project-specific documentation is kept under `docs/wiki/`.
