= OpenBangla Keyboard — Experimental Linux Fork

OpenBangla Keyboard is a Unicode-compliant Bangla input method with phonetic and fixed keyboard layouts, typing automation, dictionary support and autocorrection.

This repository is an experimental Linux-focused fork. The fork adds a portable, user-local build and installation workflow designed to work across ordinary and immutable Linux systems without installing build packages into the host system.

[IMPORTANT]
====
This is an experimental fork, not an official upstream OpenBangla Keyboard release.

The portable installer and related integration work contain AI-generated or AI-assisted code. The code is reviewed and tested incrementally, but regressions are possible.
====

== What this fork provides

* Linux-only CMake build.
* Automatic backend selection: KDE/Plasma uses Fcitx5; other desktop environments use IBus.
* User-local installation under `~/.local`.
* Isolated build environments using Toolbox, Distrobox, Podman, or Docker.
* Persistent build and staging cache under the XDG cache directory.
* Bundled Qt and required runtime libraries for the user-local installation.
* Automatic IBus component registration for user-local installations.
* A matching user-local uninstaller.

== Installation

Clone this fork with its submodules:

[source,bash]
----
git clone --recursive https://github.com/hasanmuammar/OpenBangla-Keyboard.git
cd OpenBangla-Keyboard
----

Run the installer:

[source,bash]
----
bash tools/install.sh
----

The installer automatically detects the desktop environment and chooses the input-method backend. It then selects an available isolated build environment and installs the build dependencies there.

Only the selected backend is built.

The default build parallelism is 2 jobs. To change it:

[source,bash]
----
OPENBANGLA_BUILD_JOBS=4 bash tools/install.sh
----

Build and staging data are stored in:

[source,text]
----
$XDG_CACHE_HOME/openbangla-keyboard/
----

or:

[source,text]
----
~/.cache/openbangla-keyboard/
----

when `XDG_CACHE_HOME` is not set.

== Uninstallation

Remove the current-user installation:

[source,bash]
----
bash tools/uninstall.sh
----

To remove the build and staging cache as well:

[source,bash]
----
bash tools/uninstall.sh --purge-cache
----

== Manual Linux build

The CMake project supports one input-method backend per build.

=== IBus

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=ON \
  -DENABLE_FCITX=OFF

cmake --build build --parallel 2
cmake --install build
----

=== Fcitx5

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=OFF \
  -DENABLE_FCITX=ON

cmake --build build --parallel 2
cmake --install build
----

The build requires Qt5, CMake, Ninja, a C/C++ compiler, Rust/Cargo, zstd development files, and the development files for the selected input-method backend.

== Development

The fork is developed on the `develop` branch.

After updating the repository:

[source,bash]
----
git pull --recurse-submodules
bash tools/install.sh
----

For a clean automated rebuild:

[source,bash]
----
rm -rf "$XDG_CACHE_HOME/openbangla-keyboard/build"
----

If `XDG_CACHE_HOME` is not set:

[source,bash]
----
rm -rf "$HOME/.cache/openbangla-keyboard/build"
----

Fork-specific documentation is kept under `docs/wiki/`.

== Project structure

[cols="1,3"]
|===
|Path |Purpose

|`tools/install.sh`
|Main user-local installer.

|`tools/uninstall.sh`
|User-local uninstaller.

|`tools/portable/`
|Backend selection, isolated build, runtime bundling and installation logic.

|`src/engine/ibus/`
|IBus backend.

|`src/engine/fcitx/`
|Fcitx5 backend.

|`src/frontend/`
|Qt GUI.

|`src/engine/riti/`
|Riti input engine submodule.
|===
